# PILOT Studio 1.0 구현·검증 상태

기준: 통합설계 v1.6, ASAP 설계 v0.4. 작성일: 2026-10-12. 설계 문서와 앱 버전·실제 사용자 제품 성공 여부는 각각 구분합니다.

## 연결된 기능

- 프로젝트/입력: 빈 프로젝트 생성, 제품 메타데이터, A/B 두 입력 방식, 완제품 STEP·기준 하위 STEP 다중 등록, 파일별 상태/해시·원본 보존, 저장/재열기.
- 모델/대응: 원본 배치/형상 정의/투입 단위 분리, 반복 볼트 개체 ID, 단일/복합 기하 정합 후보·공간 인접 복합 후보·기준 범위·중복 차단·수동 대응, 단위 편집/확정/리비전, 원본/OBJ/기준 형상 비교.
- 공정/공구: 작업 정의·독립 체결·가체결/최종체결·정보/토크·주의사항·공구 구성 단위/소켓·필수/선호 규칙·순환 차단, 무공구와 공구 변경 비용·최초 준비 구분.
- 생성/편집: 실제 ASAP learn/heur-out와 별도 자체 생성기·수동 계획, 실제 원시 결과/종료 원인·불변 입력, 목표 위치 미리확인·선행 위반 차단·변경 사유, 파생 계획·실제 경로의 낡은 상태.
- 검증/확정: 누락/중복·품목/규칙/공정 검토·토크·공구·한정 검토 기록, 정확한 조건의 실제 ASAP 경로 증적·별도 BREP 직선 검사·원통 공구 외형 검사, 과거/현재 상태 분리·불변 확정본.
- 전처리/진단: 원본/분석 후보의 표준/exact BREP 상태, 적응형 테셀레이션, 모든 원본 솔리드 점유 OR, SDF 저장 전후 계약·경계 질의, 단위별 프로세스/제한시간·집계, 문제 단위/쌍의 3D 강조·격리·원문/수치/근거.
- 재생/출력: 실제 행렬 경로·역순·base·전체 자세·지지·중간 상태, 확정/초안 미리보기·MP4·전체 디코딩 확인·Web ZIP·불변 스냅샷 다시 열기. 없는 경로에 임의 직선 이동을 생성하지 않습니다.
- 저장/이력: 앱 전용 MariaDB·관리 파일·Windows DPAPI 인증 설정·저장소 바인딩·개정/감사·명령 재전송 원자적 멱등성, 일관된 논리 DB/파일 백업·해시 검증·새 DATA/DB 복원·중단 복구.
- 학습: 실제 사용자 확정 이력을 사용하는 별도 로컬 선호 모델 학습/평가/저장·후보 적용. 데이터 부족과 독립 제품 평가 미확보를 정상 상태로 표시하며 기본 처리나 ASAP 추론을 막지 않습니다.
- 데스크톱: 기본 브라우저를 열지 않는 WebView2 독립 창, 패키지 런타임·개별 작업자·앱/DB 수명 관리, 사용자 데이터 폴더 저장·설치파일.

## 확보한 증적

실제 MariaDB에 두 입력 방식의 새로운 검증 형상을 등록했습니다. A는 4개 단위/4개 솔리드로, B는 복합 기준과 반복 기준 파일 2개를 매칭해 3개 단위/4개 솔리드로 실행했습니다. 실제 사전학습 ASAP의 준비·전체 순서·경로가 두 경우 모두 성공했고 공정 초안으로 반영했습니다. 각 조건에서 max_gripper=4를 명시했습니다. 기업 데이터의 공정 순서를 입력하지 않았습니다. `evidence/native-integration/summary.json`과 `evidence/asap-integration-verification.json`에 기록했습니다.

B의 원시 경로를 보존한 채 품목/작업 검토 정보를 입력하고, 전체 검증→불변 확정→실제 경로 MP4→전체 디코딩→Web ZIP→백업을 실제 HTTP/DB에서 수행했습니다. 640×360·12fps·1.5초·18프레임의 검증용 영상이며 현장 영상이 아닙니다. 동일 요청 재전송은 동일 결과로 응답했고 다른 본문의 동일 request_id는 HTTP 409로 거절했습니다. `evidence/full-workflow/summary.json`을 참조합니다.

백엔드 전체 시험은 49건 통과했습니다. 실제 MariaDB 저장·불변 해시·트랜잭션/멱등성·ASAP 파일 포함 백업·새 저장소 복원·중단/잘못된 ZIP/파일 변경 검사가 포함됐습니다. 이후 수정의 최종 회귀 시험은 24건, 데스크톱 API·저장소 선택 시험은 7건 통과했습니다. 프런트 재생·진단 시험은 25건 통과하고 TypeScript/프로덕션 빌드가 성공했습니다. 증적은 `evidence/full-tests.log`, `evidence/stable-final-tests.log`, `evidence/desktop-final-tests.log`, `evidence/frontend-verification.json`에 남깁니다. 서로 겹치는 시험 수를 더해 별도 총계로 표시하지 않습니다.

7개 화면, 실제 데이터 선택·ASAP 작업 화면·스냅샷/행렬 재생은 브라우저 QA로 확인했습니다. 컴파일된 EXE에서도 STEP 등록→기준 하위 부품 매칭→3개 단위/4개 원본 솔리드 전처리→실제 ASAP learn 순서·경로→공정 초안 반영을 통과했습니다. 엔진·Python·가중치는 배포 폴더에 포함된 파일을 사용했으며 CAD 작업자는 해당 EXE로 실행했습니다. 이 시험 역시 검증 형상을 사용했습니다. 증적은 `evidence/packaged-native/summary.json`입니다.

최종 EXE의 WebView2 독립 창은 실제 MariaDB와 UI를 로드하고 정상 종료했습니다. 기본 브라우저를 열지 않았으며 약 6.7초의 해당 PC 검증 결과는 `evidence/packaged-final-smoke/window.json`에 기록했습니다. 이 실행 시간은 모든 PC의 시작 시간 보장이 아닙니다. 설치형 빌드 검증 증적은 `evidence`의 패키지 보고서를 참조합니다. 모든 외부 설치 환경의 인수가 끝났다고 표시하지 않습니다.

단일 설치파일 `dist/PILOT-Studio-Setup-1.0.0.exe`와 독립 실행파일 `dist/PILOT-Studio/PILOT-Studio.exe`를 생성했습니다. 해당 PC의 별도 시험 폴더에 설치한 EXE의 런타임 자체 점검은 통과했고, 설치된 독립 창도 실제 MariaDB/UI 로드·외부 브라우저 미실행·정상 종료를 확인했습니다. `evidence/installed/self-test.json`, `evidence/installed/window.json`, `evidence/release-artifacts.json`을 참조합니다. WebView2 설치 조건은 실제 등록된 런타임의 공식 제품 키와 버전을 확인하며, 설치가 필요한 경우 준비 단계에서 실행하고 설치 확인 실패 시 진행을 중단합니다. 기존 런타임 탐지 증적은 `evidence/installed/component-detection.json`입니다.

최종 설치파일의 실제 설치도 성공했습니다. 준비 단계에서 기존 WebView2를 확인해 구성 요소 설치를 생략한 분기와 설치 완료를 `evidence/installed/setup-final.log`에 기록했습니다. WebView2가 없는 새 PC에서의 구성 요소 설치 분기는 아직 별도 인수하지 않았습니다.

## 실제 제품과 지원 범위

실제 HVJB는 기존 확인 도구에서 69개 확정 단위·176개 원본 솔리드의 전체 전처리/네이티브 준비 통과를 확인했습니다. 전체 순서 탐색은 30분 제한시간에 종료됐습니다. 새 제품의 완전한 HVJB 조립순서와 실제 PRA 파일의 인수는 확보하지 못했습니다. 검증용 형상 성공과 이러한 실제 제품의 미해결을 구분합니다.

매칭은 제한된 기하 후보/정합이며 모든 트리 분할·대칭·설계 버전에서 자동 대응 성공을 보장하지 않습니다. 모호한 항목은 수동 대응/확정이 필요합니다. 가스켓·와이어 등의 변형, 실제 공구 연속 이동·손/케이블·로봇 동작·제조 공차는 물리 검증 범위에 포함하지 않습니다. 공구 원통 외형은 해당 입력 자세의 보수적인 형상 검사이며 모든 공구 형상/동작의 증명이 아닙니다.

이 프로그램의 저장 구현은 앱 전용 MariaDB의 6개 업무 테이블(projects·snapshots·feedback·jobs·audit·request_log)과 2개 관리 테이블을 사용하고, 계획·작업·품목 등의 도메인 자료는 검증된 JSON 본문으로 보존합니다. 통합 기준 T-DB의 팀원 구현에 있는 19개 업무 테이블을 그대로 복제한 스키마가 아닙니다. 이 프로그램 내부의 저장·백업·복원은 시험했지만 팀원 DB의 DDL/API와 일대일 호환·기존 데이터 이관은 구현하거나 인수하지 않았습니다. 별도 팀원 DB와 통합할 때는 해당 계약의 매핑·이관 검증이 필요합니다.

외부 게시 서버·네트워크 접근 조건이 지정되지 않아 Web은 로컬 HTML/MP4 ZIP으로 제공합니다. 외부 게시 성공이나 localhost 외부 공유를 주장하지 않습니다. 공식 제품 계획 확정에는 사용자가 최신 형상·단위·필수 관계·공정/공구/토크·현장 근거를 검토해야 합니다. 사용자 승인도 실패한 실제 충돌 검사를 통과로 바꾸지 않습니다.

설치파일/실행파일 생성과 동일 PC 검증은 별도 기록입니다. Python/Node가 없는 다른 PC의 설치·CPU/메모리·드라이버·WebView2·전체 제품 성능 인수는 별도 시험으로 확인해야 합니다. 요구사항 기능 경로의 구현과 사용자 제품/설치 환경의 인수 완료는 동일하지 않습니다.
