# PILOT Studio 2.0.5 구현·검증 보고서

- 대응 명세: PILOT 구현설계 v0.6
- 최종 실행 빌드: `pilot-2.0.5-20261014T134453Z`
- 실제 제품: `KD1_HVJB_91958-KD000.stp` 및 제공 부품 STEP 18개
- 완제품 SHA-256: `3048cab7cc1dd38b1a39af1084f645c34fe91514aa88ee97e2144273b68bc2fe`

## 결과

실제 정션박스의 **78개 배치·176개 솔리드가 보존되고, 56개 조립 단위의 매칭과 고정품 제외 55단계 전체 검토 초안 생성에 성공했다. 전체 제품의 조립성 검증은 통과하지 않았다.**

기존 읽기·보정·매칭 단계에서 프로그램이 중단되는 문제와, 원본 최종 배치에 실제 겹침이 존재하는 문제를 구분했다. 후자는 순서 배열을 바꾸는 것만으로 해소되지 않는다. 확인되지 않은 단계를 통과로 만들거나 형상/작업을 누락하지 않았다.

## 구현한 흐름

STEP 등록, 원본/배치/보정 진단, 부품 매칭, 조립 단위 편집, 자체 직선 경로 검사, 제한된 후보 탐색, 순서 드래그와 재검증, 검증·정보 검토 후 확정, 회사 참고 양식/사용자 양식 MP4, 이력·전문가 선호 검토·후속 학습, MariaDB와 관리 파일, 백업·새 저장소 복원, 실행 패키지와 버전 검사를 연결했다.

기존 UI의 좌측 메뉴, 중앙 3D, 우측 작업 정보, 하단 시뮬레이션과 카드를 유지했다. 실제 모델의 56개 단위·55개 카드, 선택 연동, 비파괴 숨김, 드래그 후 자동 재검증, 최소 카드 크기와 가로 스크롤을 브라우저에서 확인했다.

## 반복 실패 분석과 수정

1. **조합 폭증으로 묶음 매칭이 끝나지 않음:** 상대 거리·배치 기반 가지치기를 적용했다. BLK 10개, PLT 9개, LV CONT 6개 구성원의 사전 조립 단위를 보존했다.
2. **일부 배치의 OCCT 유효성 실패:** 원본을 유지한 제한 보정과 BREP 저장 후 재읽기 검사를 적용했다. 문제 배치 6개가 일반 검사에 통과했지만 exact-method 차이는 검토 항목으로 남겼다.
3. **Windows 진행 파일 공유 잠금으로 작업 실패:** 원자 교체의 제한 재시도와 진행 표시 실패 격리를 적용했다.
4. **어려운 후보가 탐색 시간을 소진:** 부품 쌍·후보·전체 시간 예산을 분리하고 모든 후보의 우선 방향을 먼저 확인하도록 바꿨다. 불필요한 거리 연산을 줄이고 저비용 쌍을 먼저 검사했다.
5. **불완전한 순서만 반환:** 커버리지와 선후 관계를 유지한 55단계 검토 초안을 제공하되 미검증 경로와 전체 PASS를 분리했다.
6. **파일 교체·편집·업데이트 시 과거 결과 오사용:** 새 원본과 모델을 성공 시 함께 게시하고, 조건 해시·개정·빌드가 다른 검증의 확정을 차단했다. 요청 ID 본문 충돌도 거절한다.
7. **영상 품질과 확정 조건:** 낮은 해상도의 정보 영역 넘침, 첫 이동 부품이 화면 밖인 구도, 마지막 프레임의 미도착, 빈 주의사항 검토 누락을 고쳤다. 영상 저장 후 현재 확정 상태가 풀리는 문제도 수정했다.

8. **영상 출력 후 다음 실행 차단:** 번들 브라우저가 설치 폴더에 로그를 기록해 파일 무결성 검사와 충돌했다. GPU 하위 프로세스는 로그 경로 옵션만으로 해결되지 않아, 배포 원본과 해시를 대조한 버전별 브라우저 사본을 사용자 데이터에서 실행하도록 수정했다. 사본은 잠금과 원자 교체로 준비하고 매번 재검증한다. 변조된 DLL이나 추가 실행 모듈을 거부한다. 영상 출력 이후의 설치 파일 무결성과 앱 재시작을 출시 검사에 추가했다.

## 실제 정션박스의 남은 조건

최종 소스의 240초 생성 시험에서 20개 겹침 쌍을 확인하고 113개 쌍은 미판정으로 남겼다. 별도의 180초 전체 검증에서는 15개 겹침 쌍과 119개 미판정 쌍을 기록했다. 이 수치는 각각의 예산에서 확인한 수이며 제품 전체 겹침의 총개수가 아니다.

확인된 사례에는 PLT–LV CONT 약 216.137 mm³, M6 볼트–하우징 약 123.3 mm³, M5 볼트–하우징 약 59.845 mm³, 너트–PLT 약 29.379 mm³, AIR-BENT–하우징 약 13.764 mm³가 있다. 설계상 끼워맞춤인지 실제 형상 문제인지는 회사의 근거로 검토해야 한다.

현재 구현은 승인한 두 단위의 **국소 영역과 최종 진입 구간**에만 결합 정책을 적용한다. 입력 자료가 잘못됐다면 수정 STEP으로 다시 검증해야 한다. 승인자·허용 영역·현장 통과 결과를 임의로 만들지 않았다.

복잡한 형상에서 시간 예산 안에 증명되지 않은 경로도 남아 있다. 예산을 늘린 별도 시험에서 하우징이 고정된 실제 BUS-KD300의 첫 삽입 경로는 최종 소스로 연속 검사를 통과했다. 이는 전체 55단계 통과를 의미하지 않는다. 실제 CAD 두 단위만 사용한 제한 시험의 PASS 역시 전체 제품 통과와 구분한다.

## 확인한 시험

- 회귀 시험 49개: 애플리케이션 불변조건 17, 매칭·경로 검사 20, 실제 MariaDB 저장·복원 및 릴리스 12.
- 합성 STEP 실제 HTTP 흐름: 등록 → 전체 PASS 순서 → 토크/주의사항 검토 → 확정 → MP4 → 편집 무효화 → 재검증 PASS.
- 최종 MP4: 18프레임 전체 디코딩, 길이 1.5초, 마지막 장면 시각 1.5초. 화면 전체 프레임에서 이동 형상·한글 주의사항·5 N·m·단계 정보를 확인했다.
- 오류 복구: 불량 STEP 재등록 실패 뒤 이전 정상 원본·모델 연결 보존.
- 실제 자료 백업·복원: 새 저장소의 78개 BREP/표시 장면, 확정 이력·영상 해시, 복원된 합성 모델의 재검증 PASS.
- UI: 56개 단위·55개 카드, 선택/숨김, 순서 변경·재검증, 소수 거리 입력, 좁은 화면, JS/console 오류 0건.
- 영상 레이아웃: 640×360, 1280×720, 1920×1080의 정보 영역과 패키지 한글 글꼴 확인.

## 인수 범위

현재 실행 패키지에서 남은 구현은 상세 공정 편집(역할·체결 대상·완료 조건·초기 장애물 전용 화면), 연속 편집의 자동 검증 예약, 자유로운 템플릿 필드 배치, 과거 확정본/양식 선택 재출력 화면, 휴리스틱/ML 전체 계획 자동 비교 및 평가 요청 패키지다. 현재 수동 초안 작성, 기본 공정 규칙, 드래그 재검증, 템플릿 출력, 전문가 후보 쌍 학습과 회사 평가 입력은 동작한다. 이 차이는 설계서 §0.0에도 명시했다.

회사 양식 최종 승인, 실제 제품의 결합 허용 범위, 공정 토크·주의사항, 회사 기준 유사도 자료, 실제 작업자 필드테스트는 아직 완료된 것으로 표시하지 않는다. 학습 모델은 실자료와 검토 기준이 충족되기 전까지 휴리스틱을 교체하지 않는다.

이번 검증은 현재 Windows 개발 PC와 독립 시험 저장소에서 수행했다. 개발 도구가 전혀 없는 별도 PC의 인수, 기존 v1 운영 DB 자동 이관, 사용자 레지스트리의 실제 설치 변경까지 통과한 것으로 확대하지 않는다.

## 최종 실행 패키지 검증

- 설치 파일: `PILOT-Studio-2.0.5-Setup.exe`, 741,927,523바이트. 패키지의 4,074개 파일 무결성을 검사했다.
- 설치 파일 SHA-256: `01addffb3e2898109e32ab9e3577a056b0418fbc35f1d966ab2634f045b3f668`.
- 개발 서버가 아닌 동결 백엔드에서 합성 STEP의 실제 등록·PASS 생성·확정·MP4·편집 후 무효화·재검증·불량 재등록 복구 등 9개 검사를 통과했다. MP4 18프레임을 전체 디코딩했고 출력 뒤 설치 자원의 해시가 유지됐다.
- 패키지의 Electron 창에서 실제 3D와 순서 시뮬레이션을 실행하고 종료했다. 같은 고정 런처로 두 번 연속 다시 실행해 매번 현재 빌드와 설치 자원 무결성을 확인했다. 화면 JS 오류는 0건이다.
- 실제 네이티브 2.0.2에서 2.0.5로 활성 버전을 바꾸고 프로젝트 ID·개정·기존 백업 보존과 업데이트 전 백업 생성을 확인했다. 새 실행 파일이 잘못된 경우 이전 활성 버전과 데이터가 유지됐다.
- 이 업데이트 시험은 독립 시험 디렉터리에서 수행했다. 사용자의 기존 운영 설치·레지스트리 또는 구형 세대 DB를 변경한 시험이 아니다.

최종 2.0.5 동결 패키지에 실제 완제품 STEP과 부품 STEP 18개를 새로 등록해 78개 배치·176개 솔리드·56개 조립 단위와 55단계 전체 검토 순서를 다시 확인했다. 전체 검증 상태는 `BLOCKED`이며, 미검증 계획의 확정 요청은 거절됐다. 실제 화면의 55개 카드와 3D 장면, JS 오류 0건, 처리 후 설치 자원 불변을 확인했다.

`HVJB_검토용_프로젝트_v2.0.5.zip`은 이 최종 실행의 원본·모델·순서·진단을 담은 백업이다. 백업 전체 무결성을 검증했다. 물리적 조립 승인본이 아니며 같은 프로그램의 저장소·환경에서 복원하여 검토할 수 있다.

기계 판독용 시험 요약은 `PILOT_2.0.5_검증결과.json`, 배포 파일의 크기·해시는 `PILOT_2.0.5_배포파일_SHA256.json`에 기록한다.
